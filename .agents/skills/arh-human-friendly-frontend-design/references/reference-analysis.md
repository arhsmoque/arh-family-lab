# Visual Reference Analysis

Inspect every supplied artifact before proposing to recreate it. Treat references as evidence of relationships, not a license to copy identity or implementation.

For each reference, record:

```yaml
reference:
  source: ""
  appealed_traits: []
  rejected_traits: []
  composition:
    hero: ""
    section_rhythm: ""
    density: ""
    hierarchy: ""
  expression:
    warmth: ""
    maturity: ""
    energy: ""
    imagery: ""
  transferable_principles: []
  non_transferable_identity: []
```

Synthesize across references:

- Repeated appealed traits become candidate invariants.
- Explicit dislikes become anti-patterns.
- Layout references inform composition, not palette by default.
- Palette references inform semantic roles only after contrast and state validation.
- Domain-specific behavior transfers only through the target product's real functional seams.

Never claim visual inspection from page text alone. Use screenshots or supplied images when appearance is material, and distinguish observed visual evidence from creator descriptions.
